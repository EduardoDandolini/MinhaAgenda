## Questão 1

A classe MauiProgram é responsável por configurar a infraestrutura da aplicação no momento da inicialização. Ela segue uma abordagem baseada em injeção de dependência , permitindo que os serviços da aplicação sejam registrados e posteriormente utilizados de forma desacoplada, promovendo uma arquitetura limpa.
O primeiro serviço registrado é IRepositorioDeContatos, que é implementado por RepositorioContatosSqlLite. Este componente representa a camada de acesso a dados, responsável por realizar operações de leitura e escrita no banco de dados. Seu papel é isolar o armazenamento dos dados da lógica de negócio, permitindo que a aplicação funcione mesmo se a tecnologia de persistência for trocada futuramente.
Em seguida, os casos de uso são registrados como serviços. Esses casos de uso representam a camada de aplicação e encapsulam as regras e fluxos de negócio da aplicação. O IVisualizarContatosUseCase é responsável por orquestrar a visualização da lista de contatos, consultando o repositório e organizando os dados para apresentação. O IApagarContatoUseCase gerencia o processo de exclusão de contatos, garantindo que apenas dados válidos sejam removidos. O IAdicionarContatoUseCase trata da criação de novos contatos, realizando validações e repassando as informações para o repositório. Já o IEditarContatoUseCase lida com a atualização de dados, cuidando para que as alterações sejam consistentes e válidas.
As páginas ContatosPage, EditarContatoPage e AdicionarContatoPage também são registradas como serviços, o que permite que elas recebam suas dependências via injeção. Essas páginas compõem a camada de apresentação da aplicação, sendo responsáveis pela interação com o usuário e pela exibição das informações gerenciadas pelos casos de uso.
Essa estrutura demonstra a aplicação de princípios da arquitetura limpa (Clean Architecture), onde há uma separação clara entre as camadas de apresentação, aplicação e infraestrutura. A comunicação entre essas camadas é feita por meio de interfaces, permitindo a substituição de implementações com impacto mínimo no restante da aplicação. Isso proporciona maior testabilidade, facilidade de manutenção e modularidade.
